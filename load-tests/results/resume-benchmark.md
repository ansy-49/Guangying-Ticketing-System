# 简历用性能对照报告

测试时间：2026-09-24

## 1. Caffeine 热缓存 A/B

测试接口：`GET /ajax/movieOnInfoList`

固定条件：同一台机器、同一 JAR、同一 H2 数据集、JVM 堆 192-384 MB、预热 100 次、正式请求 3000 次、并发数 100。唯一变量为 `guangying.cache.enabled`。

| 指标 | 关闭缓存（数据库直查） | 开启 Caffeine 热缓存 | 改善 |
| --- | ---: | ---: | ---: |
| 成功率 | 100% | 100% | 持平 |
| 吞吐量 | 2470.32 RPS | 4287.08 RPS | **+73.54%** |
| 平均延迟 | 40.01 ms | 23.09 ms | **-42.29%** |
| P50 | 37.18 ms | 18.99 ms | **-48.92%** |
| P95 | 69.34 ms | 48.84 ms | **-29.56%** |
| P99 | 93.38 ms | 65.71 ms | **-29.63%** |

推荐简历表述：

> 针对电影列表热点读场景，引入 Caffeine 本地缓存并支持 Redis 二级缓存与降级策略；在 3000 请求、100 并发的本地 A/B 压测中，接口吞吐量由 2470 RPS 提升至 4287 RPS（+73.5%），平均延迟由 40.0 ms 降至 23.1 ms，P95 由 69.3 ms 降至 48.8 ms。

## 2. 库存并发正确性与有效吞吐

| 指标 | 版本号乐观锁 | 条件原子扣减 | 改善 |
| --- | ---: | ---: | ---: |
| 100 个不同座位成功订单 | 6 / 100 | 100 / 100 | 成功率 6% → 100% |
| 有效下单吞吐 | 9.83 单/秒 | 96.42 单/秒 | **+881.2%** |
| 100 人争抢同一座位 | 1 单成功 | 1 单成功 | 均为零超卖 |

推荐简历表述：

> 优化高并发锁座链路，将易产生版本冲突的库存乐观锁改为 MySQL 条件原子扣减，并结合 Redis Lua 锁座与数据库唯一索引形成多层防超卖；100 并发不同座位下单成功率由 6% 提升至 100%，有效吞吐由 9.8 提升至 96.4 单/秒，同时保证同座争抢零超卖。

## RocketMQ 应该怎么写

当前 RocketMQ + Outbox 的主要价值是可靠性和解耦，不是已经被本次压测证明的毫秒级提速。推荐写：

> 基于 RocketMQ 与本地消息表 Outbox 解耦订单领域事件，业务数据与待发送事件同事务落库，并通过定时重试实现最终一致性，避免消息中间件短暂故障导致订单事件丢失。

不要写“RocketMQ 将接口耗时降低 X ms”，除非另做同步发送 MQ 与 Outbox 异步投递的严格 A/B 测试。
